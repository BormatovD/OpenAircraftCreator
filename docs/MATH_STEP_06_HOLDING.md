# Математика — шаг 06: Green Dot holding / final reserve A320ceo

**Дата:** 12 ноября 2026. **База:** установленный `MATH_STEP_05_DESCENT`.

## Источник и границы

China Eastern A319/A320/A321 FCOM V3, PDF-страница **1826**, `PERFORMANCE / HOLDING`, исходный набор `data/fcom/a320-214-ces-phases.json`. Для A320-214/CFM56-5B4/P: Green Dot, clean, racetrack, NORMAL A/C, anti-ice OFF, ISA0. Зависимость от массы и высоты (FL15 ... FL250) извлечена и проверена в предыдущем пакете.

**FF (KG/H/ENG)** — расход на один двигатель. В миссии умножается на **два**, затем на количество часов. Операционное правило планирования Volume 2 (PDF стр. 647) задаёт массу **при посадке на запасном аэродроме** как базовую для 30-минутного ожидания; эта масса в коде `landingMassKg - alternateKg`.

Для опорного A320 включено `fcomHoldingFL = 15`, то есть ожидание 1500 ft над запасным аэродромом при допущении о его высоте на уровне моря. При отсутствии табличной точки или других вариантах самолёта остаётся исходный физический расчёт `holdTsfcRatio=0.8`. `finalReserveMode="cruise"` не переключается на Green Dot.

## Табличная контрольная точка

При **60 000 кг / FL15**:

- `1128 кг/ч/двигатель`;
- `1128 × 2 = 2256 кг/ч на самолёт`;
- за 30 минут: `2256 × (30/60) = 1128 кг`.

Здесь масса является *планировочной* константой таблицы: в отличие от физического интегрирования TSFC мы не уменьшаем её при выработке топлива на ожидание. Это следует явно учитывать при интерпретации резерва.

## Что не меняется

- Физический крейсерский TSFC не подгоняется.
- FCOM holding не распространяется на A319/A321/NEO или изменённые конструкции.
- Резерв при недостатке данных не выдумывается: в `Reserves.finalReserveSource` доступен признак `physical-uncovered`.
- Резервы на запасной аэродром продолжают считаться прежним отдельным методом, без применения таблицы набора от отпускания тормозов.

## Локальные проверки и ограничения

Пять тестов ожидания (расход на двигатель, масса запасного, покрытие, режим `cruise`, переносимость на другие варианты) и шесть тестов снижения прошли на восстановленном исходном срезе (локальная тестовая ISA). Итого 11 изолированных тестов. **Полный `npm test`, typecheck и build на пользовательском Git остаются обязательными**, поскольку в рабочей среде не было полного дерева проекта.

Изолированное сравнение сценария 810 nm на приближённой тестовой атмосфере, *не на актуальном Git пользователя* (сравнивать только разницу методов, а не абсолютные числа):

| Сценарий | Взлётное топливо с резервами, кг | Рейсовое топливо, кг | Финальный резерв, кг |
|---|---:|---:|---:|
| С предыдущим табличным набором | 7391,2 | 4762,7 | 789,9 |
| + Табличное снижение и IFR-заход | 7270,6 | 4648,0 | 789,8 |
| + Только табличное Green Dot ожидание | 7757,1 | 4789,6 | 1123,5 |
| Оба изменения | **7634,8** | **4673,2** | **1123,4** |

Это не новая калибровка. При других температурах, крыле, Махе и массе FCOM применять нельзя. Особое ограничение: `WEIGHT` таблицы чистого снижения требует отдельного инженерного подтверждения (см. MATH_STEP_05_DESCENT.md).

## Что делаем

1. Прогнать на текущем репозитории `npm test && npm run typecheck && npm run build`.
2. Сверить пофазную сумму топлива и условия табличных точек на A320.
3. Проверить 500/810/1500/2500 nm; отдельно посмотреть, улучшилась ли короткая миссия и сохраняется ли знак ошибки относительно ACAP.
4. Сверить A319/A321/NEO и 737/757 — их численные результаты не должны поменяться без явного изменения модели.
5. Дальше — аудит массы 757, затем определение Ту-214. Не закрывать отдельно невыполненную проверку крейсерского расхода (−10% к CES FCOM) и пик коротких рейсов 737-8.
