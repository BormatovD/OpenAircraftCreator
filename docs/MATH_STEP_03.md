# Математика — шаг 03.1. Табличный набор A320ceo

Дата: 12 ноября 2026. База: установленный `MATH_STEP_02`.

## Граница изменений

Подключён **только набор** для опорной конфигурации A320-214, CFM56-5B4/P SAC, исходная геометрия с wingtip fences; источник `data/fcom/a320-214-ces-phases.json`, China Eastern FCOM Volume 3 (2007), PDF стр. 1637 и 1644. Название двигателя в текущем объекте `A320CEO` пока обобщённое («CFM56-5B»); использование здесь означает допущение о применимости модификации /P, отмеченное в протоколе.

Таблица дана при ISA0, NORMAL A/C, anti-ice OFF, CG 33%, MAX CLIMB THRUST, закон скорости 250 kt/300 kt/M0.78. Масса — **при отпускании тормозов**, топливо — **накопленное от brake release** и уже включает взлёт и начальный набор.

Для базового A320 из `contextFor(A320CEO)` таблица подключается в `comparisonAssumptionsFor`. `A320_CONTEXT` для калибровки и независимых ACAP-графиков **не получает** её автоматически. При любом изменении определения или ненулевом списке рычагов через `evaluateResolved` таблица отключается. Другие типы, в том числе NEO, её никогда не получают. В `simulateTrip` при ином M, LRC, ΔISA, недостаточной области покрытия, короткой миссии либо на запасной аэродром остаётся энергетическая оценка. Никакой экстраполяции отсутствующих ячеек.

## Табличный баланс

Для TOW 60 000 кг и FL350:

| Величина | FCOM | Прежняя энергетическая модель (локальный воспроизводимый срез) |
|---|---:|---:|
| Накопленное топливо FL15 | 163 кг | отдельные 90 кг (взлёт) |
| Топливо от FL15 до FL350 | 1254 кг | ≈1218,4 кг |
| Топливо всего от brake release | **1417 кг** | **≈1308,4 кг** |
| Накопленная дистанция набора | **114 nm** | **≈102,6 nm** |
| Накопленное время | **18 мин** | не рассчитывалось отдельно |

В коде `TripResult.takeoffFuelKg` означает здесь **топливо до FL15**, а `TripResult.climbFuelKg` — последующее топливо. Их сумма соответствует исходным 1417 кг; 90 кг не добавляются второй раз. `climbDistanceNm` и `climbTimeMin` сообщаются отдельно.

`rangeForFuel` использует табличную дистанцию для уменьшения оставшегося горизонтального крейсера, а не просто добавляет топливо. Общее рейсовое топливо по-прежнему сохраняется по закону баланса: взлёт + набор + горизонтальный крейсер + ступенчатые наборы + снижение.

## Ограничения

1. Таблица первого набора от brake release **не** используется для перелёта на запасной аэродром.
2. Для коротких рейсов, когда полного набора нет, применяется прежняя энергетическая оценка с пометкой `energy-short-route`. Разделить табличный набор по произвольной высоте в рамках такой миссии пока нельзя.
3. Исходный подбор эшелона использует массу после оценочного взлёта (90 кг), даже если затем применяется FCOM; это небольшое, но пока не устранённое расхождение условия выбора эшелона в приграничных точках.
4. Топливо ступенчатых наборов после TOC всё ещё оценивается энергетически.
5. Снижение (**300 кг**) и ожидание (`holdTsfcRatio=0.8`) пока сохранены — **не** считать этот шаг полной фазовой калибровкой.
6. Ни один коэффициент аэродинамики, массы или TSFC не изменён. Опорный TSFC остаётся 0.586 lb/(lbf·h).

## Проверки

Дополнительно ключ кеша `contextFor` теперь включает определение целиком; модификации с одинаковым id не смешиваются.

`test/fcom-climb-integration.test.ts`: табличный узел, отсутствие двойного счёта, обратная совместимость энергетической модели, запасной аэродром, недопустимая ISA и масса, короткая миссия, ограничение на исходное крыло/двигатель. В изолированной проверке восстановленного исходного среза все 7 новых тестов и 4 теста бюджета фаз прошли. Полные тесты на рабочей копии пользователя нужно выполнить после применения патча.

## Что делаем

1. Устанавливаем этот патч и подтверждаем `npm test && npm run typecheck && npm run build`.
2. Запускаем независимую сверку из шага 04 без изменения TSFC.
3. Следующей отдельной инженерной задачей согласуем *массу таблицы снижения* и фазу захода, затем исправляем ожидание по Green Dot и заново оцениваем остаточные ошибки крейсера.
